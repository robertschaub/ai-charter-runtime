# Agent rules — ai-charter-runtime

The authoritative working rules for AI agents and humans in this repository. The tool wrappers — [CLAUDE.md](CLAUDE.md), [GEMINI.md](GEMINI.md) and [.github/copilot-instructions.md](.github/copilot-instructions.md) — point here; if they ever diverge, **this file wins**, subject to system/developer instructions and the current user task. Read applicable nested instructions before target work.

- **The spec is authoritative.** Build to [docs/spec/runtime-gates-poc-spec.md](docs/spec/runtime-gates-poc-spec.md); on divergence the spec and its linked Charter sources win. The implementation specification and its system-use companion live in this repository beside the code they govern. Broader Charter obligations and concepts remain authoritative in `our-ai-charter`.
- **EGA preparation.** Runtime is technical preparation for Evidence-Gated Agents alongside its recorded demonstrator/article purpose. For assigned EGA-related work, map task-supplied requirements and the linked public EGA sources to this repository's specifications and ADRs, identify compatible reuse and gaps, and record them in the task's authorized record home. Preserve adopted contracts and milestone scope; material changes require explicit approval and reviewed specification/ADR edits here. Public contributors must have the implementation contracts they need in this repository and its public sources, without an unpublished-document dependency.
- **Licensing follows material type and path assignments** — [Licensing guide](LICENSING.md) is the map; every source file carries a matching `SPDX-License-Identifier` header. Do not move code across the software/documentation boundary without updating the map.
- **Honesty rules:** this is a maintainer sketch, not a certification artifact ([NOTICE](NOTICE)). No green-light surfaces, no "queryable certification", no claims of independent assurance. Test-family coverage is marked exercised / partial / not assessed — never implied.
- **Repository access and disclosure.** Treat this repository and every commit as public and permanent. Use the public Charter/spec sources above and the task's authorized repositories and read/write scope. If another repository is needed, ask once, naming it, the purpose and read/write access; continue independent work while waiting. Approval covers this task and its handoffs until changed; do not ask again for the same scope. Authorized reads may include private material, but keep private names/paths, secrets, real personal data and confidential records out of this repository and public artifacts. Public links must not depend on local paths or unpublished context. Use MCP only for its identified source repository; availability is not authority. If MCP is unavailable or unqualified, use authorized direct reads. Access does not grant disclosure permission or change runtime authorization.
- **Secrets and test data:** keys live only in gitignored `.env.local`; never in code, logs, fixtures, records, or probe output. Fixtures and tests use synthetic data only; never use real personal data.
- **Git & safety:** ordinary solo work uses `main`; concurrent writing uses integrator-supplied task worktrees, disjoint owned files and one integrator for shared records/Git integration. Restricted writers return edits/evidence without staging, commits, merges, pulls, branch/worktree creation/switches or shared-settings/hook changes. Ordinary explicitly authorized worker-commit modes remain available outside the instruction-system rollout. The maintainer decides when to push. Conventional commits (`type(scope): description`). When loaded and trusted, the shared **PreToolUse hook** ([.claude/settings.json](.claude/settings.json), mirrored in [.codex/hooks.json](.codex/hooks.json)) screens destructive Git forms including hard resets, non-lease forced pushes, forced cleans, and broad checkout/restore discards. Hook coverage is a backstop, not a guarantee — it may be untrusted, skipped for some tools, or absent in subagents — so never delegate destructive git to a subagent; keep it in the main session or do it by hand. To undo, prefer a revert commit.
- **Verification and stateful tooling.** Normal local checks are `npm run typecheck`, `npm test`, and, for model-card changes, `npm run cards:verify`. Explicit maintainer approval is required before `npm run probe` or direct `tooling/probe.mjs` calls, which contact external model APIs and write probe results; before `tooling/keys.mjs generate|rotate-hmac|gen-card-keys`; and before `tooling/cards.mjs sign`, which changes signed public artifacts and may change the trust root.
- **GitHub posture** (applied 2026-08-01 at repo creation; adapted from the sibling repos): visibility **public**; human repository access is limited to the maintainer account, with no collaborators, deploy keys, or webhooks. The OpenAI Codex GitHub App is the sole explicitly approved exception and currently has access to this repository; treat it as write-capable, keep its repository selection minimal, and remove it when no longer needed. No additional GitHub Apps or integration-scope changes without explicit maintainer approval. Secret scanning + push protection, Dependabot alerts, and private vulnerability reporting are **enabled**; `main` is protected against force-pushes and deletion. GitHub Actions are restricted to what the repo actually needs (none yet — add deliberately, never copied wholesale from FactHarbor). Public issues stay open for feedback, but gate-bypass and record-integrity findings go through the private route in [SECURITY.md](SECURITY.md), specification and ADR questions belong here beside the code, and Charter-principle/public EGA-concept questions belong in `our-ai-charter` ([.github/ISSUE_TEMPLATE/config.yml](.github/ISSUE_TEMPLATE/config.yml) provides the Charter and security routes; ordinary Runtime issues remain available).
- **Records are part of the system under test**: never hand-edit files under `records/`; tamper tests do it deliberately via the test harness.
- **Platform:** Windows — use PowerShell-compatible commands (`$env:VAR`, `$null`, backtick continuation). Node ≥ 20, ESM; LF line endings enforced by [.gitattributes](.gitattributes).
- The gate invariants are non-negotiable in code review: model output never authorizes; a signal has no code path to allow; ambiguity or missing authority fails closed. In the reviewed dynamic-session/native path, the orchestrator invokes only explicitly allowlisted, authorization-owned operations, notably fixed precommit; it supplies no authority facts and chooses no ruling. The caller-carried `/actions/execute` and escalation-revision paths remain synthetic headless-test seams; they may request a gate ruling or submit a revision, but authorization alone evaluates and records the result. The orchestrator cannot change standing authority, invoke `commit-verify`, receive a Commit token, or create an effect. Every consequential effect requires a valid single-use commit token.

## Agent workflow boundaries

**Delegated model selection:** For an authorized agent call (Codex, Claude Code, Gemini or another client), honor explicit user model, effort and provider choices. Otherwise choose a supported model and effort suited to task complexity, risk, context, latency and authorized cost, without asking for model confirmation. State the choice and brief reason before dispatch; verify actual settings where exposed. If an agent-selected model is unsupported or unavailable for a non-quota reason, announce one suitable alternative within the same authorized provider, authentication and spending limits before retrying. Authentication or quota failures stop the call; do not switch models, accounts or providers to bypass them. Ask before changing a user-fixed selection or exceeding authority. Claude calls use subscription authentication only, never API fallback. This governs delegated calls only: it grants no delegation, access, disclosure, execution or spending permission, changes no current-session or application model/configuration, and resumes no paused work.

Use focused verification appropriate to the change and assigned writable state. A trivial documentation change needs no broad suite or completion file. Independent review is required for material authorization/security/record-integrity claims and when requested. Reuse an existing task record for decisions, exact reviewed-content evidence, checks and integrated SHA mapping; restricted reviewers return chat findings.

Strict read-only diagnosis/review reads source and captured output; it runs no tests/builds, writes no recovery logs/cache/records, and performs no Git mutations or live operations. If reproduction is needed and authorized, assign diagnosis/reproduction together with disposable output/cache/temp paths. Do not label that session read-only.

Before restricted dispatch, record permitted commands/state, control mechanisms/locations, trust/activation, installed verification and unknowns. The existing Codex verify sandbox declaration and Claude Read/Grep/Glob definition are read-only reference profiles, not proof of effective enforcement. Do not broaden their tools; do not dispatch a writer whose required restriction is unsupported. Worktrees and stronger models are not containment.

Pushes, deployments, live analyses, and provider-spending operations require current authorization covering the specific action and scope. Authorization already given in the task remains valid; preparation or review alone does not grant it. The specific key-generation/rotation, signing and live-probe gates above also persist. Review/skill selection grants none of those actions.

These agent-workflow rules do not change deterministic runtime authorization, fail-closed decisions, single-use tokens, source pins, licensing or the ban on hand-editing records.

## Documentation sources

Keep public setup, implementation contracts and contribution instructions usable from this checkout alone. Before changing document authority or retiring records, read any task-supplied reference brief and preserve current rules, unresolved work and provenance. Use additional material only within the task's explicit access and disclosure scope. Keep local reference locations, confidential records and dependencies on unpublished material out of public files and generated outputs.

Use the current task or a verified, human-adopted workspace profile for cross-repository scope. Durable working notes, detailed investigations, handoffs and unpublished prototypes use their assigned non-public record home unless clearly authorized as public. Existing public source, tests, operative configuration and contribution contracts stay here. A public cwd or a missing confidentiality marker does not select a public destination. If an assigned record home is unavailable, preserve permitted pending work outside this checkout and report the persistence gap; never recreate a private collection here.

Select the primary checkout for the main deliverable. Explicitly read root and nested instructions for every target repository, run commands with an explicit working directory, and verify each tool's served source/revision. Additional-directory access does not load all instructions, hooks or skills; if required write controls cannot be verified, continue that write in a fresh target-primary session. A code worktree does not isolate a paired documentation checkout. Keep separate revisions and one owner per shared record.

Contributors without an assigned private home may use the public record paths for intentionally public, public-safe work; uncertain or non-public material stays in the authorized task/chat scope.
